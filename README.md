# scanplan

Turn an iPhone LiDAR scan, a walkthrough video, or a folder of photos into a measured,
stitched floor plan — with damage regions, concealed-damage flags, a repair scope, and a
90% interval on every number.

Built for the Cozmo AI Applied AI case study. Start with
[`docs/gates.md`](docs/gates.md) for what is being measured and
[`docs/capture_protocol.md`](docs/capture_protocol.md) for how to capture.

## Status

| Tier | Input | State |
|---|---|---|
| LiDAR | Stray Scanner export folder | contract + tier detection; geometry in progress |
| Video | `.mov` from the Camera app | contract + tier detection; geometry in progress |
| Photo | one folder per room, 2–8 stills each | contract + tier detection; geometry in progress |

Measurements are not real yet: every run emits a `PIPELINE_STUB` warning until the geometry
stages land. The contract, the schema and the validator come first deliberately, so that no
later stage has anywhere invalid to write.

## Install (clean machine, under 15 minutes)

Needs Python 3.10–3.12 and ffmpeg.

```bash
git clone <this repo> && cd scanplan
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"          # geometry only, no model weights
pip install -e ".[dev,models]"   # adds the video and photo tiers (~3 GB of weights)
pytest -q
```

On a CPU-only Linux machine, install PyTorch from the CPU index **first**, or pip will pull
~2.5 GB of unusable CUDA libraries:

```bash
pip install "torch>=2.4,<2.10" "torchvision>=0.19,<0.25" --index-url https://download.pytorch.org/whl/cpu
```

## Run — one command per capture

```bash
scanplan run path/to/StrayScannerExport    # LiDAR
scanplan run path/to/walkthrough.mov       # video
scanplan run path/to/home                  # photos: home/kitchen/*.heic, home/bedroom 1/*.heic
```

The tier is detected from the input. Each run writes `out/<name>/result.json` (validated
against [`schema/output.schema.json`](schema/output.schema.json)), plus `plan.svg`,
`summary.md` and `report.pdf`.

Other commands:

- `scanplan inspect <capture>` — what the pipeline thinks it was handed
- `scanplan validate <result.json>` — check a result against the schema
- `--no-drift` — the G-DRIFT on/off ablation
- `--no-damage` — skip damage detection

## Design

Three front-ends, one core. Each tier populates the same [`CaptureIR`](scanplan/ir.py);
everything downstream — layout, error model, export, benchmarks — sees only that. The tiers
differ almost entirely in how metric scale is recovered, which is why scale is an explicit
field with a stated provenance and sigma rather than an implicit assumption.

The LiDAR path uses **no neural models at all** — pure geometry over depth and poses. That
keeps the fastest and most accurate tier deterministic and dependency-free for a cold run.

## Ground truth and benchmarks

Measurement conventions are fixed in [`gt/README.md`](gt/README.md) before any measuring
starts, and are used identically for our output, the laser ground truth, and the head-to-head
app. Every reported number is regenerated by a script in `bench/`.
